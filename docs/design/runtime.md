# 节点运行与配置

节点是独立进程，主动以专用凭据连接服务端 HTTPS/WSS。启动先取得节点目录 OS 锁，读取配置与持久检查点，核验每个 AI 的绑定，再补齐来源失效和任务状态。模型 Key 在节点本机解析，不能进协议、日志、命令行或目录响应。HTTPS/WSS 保持证书验证，私有 CA 显式配置。

角色、模型参数、记忆和摘要属于节点；云端负责账号、窗口、权限和任务。配置保存先完成事务，新运行使用新快照，在飞请求不切换模型。未加密在线管理按 requestId 去重，回执只存指纹，节点保存才成功；离线不排队修改。sealedV1 资料用密文 CAS，同步成功与当前绑定 applied 分别确认。

`catalog` 和 `--version` 不读取节点、配置或凭据，不联网和创建数据；catalog 的版本契约来自 connector。`check <directory>` 校验完整模型配置，不静默替换模型或回退内置副本。

普通 `run` 运行云端连接；桌面通过独立程序的 `run-managed` 管理同机通道，Windows 使用命名管道，Unix 使用本机 socket，不开放公网或局域网端口。通道 token 保留在受限节点目录。托管状态与停止使用目录锁和实例 UUID，不按任意 PID 终止；ready 确认之前不能报告启动成功。客户端关闭窗口可让节点继续运行，停止则结束任务与流并保留检查点。

在线控制帧先被 select 接收，再完整处理管理命令；不能将已消费命令的异步持久化放在可取消分支。节点停止、崩溃或失去绑定后，已开始结果未知的调用按 uncertain 收尾，绝不自动重做。新节点重新授权，旧账号和云端历史沿用；迁移包不带凭据或执行任务。

客户端使用固定版本的 Agent 程序、目标平台与 SHA-256，不从兄弟仓源码隐式构建。节点路径及数据格式不因拆仓改变。CLI 与桌面管理具体用法见[节点说明](../../node/README.md)，执行和意识规则见[执行](execution.md)与[意识系统](consciousness.md)。
